How I work

Ship small, then measure

At Wizz each feature started from a KPI goal and went out behind an A/B test. Plenty were killed. I still work that way: release, read the numbers, keep or cut.

Own the release pipeline

I've written the CI/CD and the CLIs on my last two teams, so a small team can get from merge to TestFlight to App Store review without manual steps.

Native where it counts

Swift and UIKit for the parts users touch most, like a feed that has to scroll without a hitch. SwiftUI and shared modules where they save time.

Past the app boundary

I like building tools and automating anything I end up doing twice: CLIs for my teams, a Claude Code skill for releases, agent jobs for my own mornings. When a feature needed it, I've also written some backend code in JavaScript, and I taught Java at Le Cnam.
